# Compact 12-host train/test protocol

Run `bash run_12_images.sh --resume` or `bash run_all.sh --profile compact12 --resume` (the default profile of run_all.sh is now compact12). No image downloads. Both `--profile paper` and `--profile compact12` route to the same compact protocol. Only the explicitly selected legacy `--profile full-paper` (or legacy lite/stress) invokes the old external-data pipeline.

Exactly 12 bundled BMPs, partitioned by deterministic seed 2026: 4 training/calibration and 8 test. No validation. Split is checked for file/native/processed duplicates, and saved in `results/compact12_real_watermarks/image_split.json`. These are previously used legacy hosts, so the test split is held out from this run's calibration, not externally independent or necessarily unseen during algorithm development.

Train: all 36 existing baseline strength candidates per host, one key; the existing selection objective (qualification, then distance to 55 dB, then BER) is unchanged. Proposal hyperparameter sensitivity (115 settings per train host, one key) is descriptive; FC-AOIP defaults remain frozen, not selected from test data. The chosen five baseline strengths are frozen in `frozen_config.json` and used only for the main comparative image robustness experiment. A candidate with zero qualification is not guaranteed PSNR-matched; report actual PSNR, clean BER and qualification rates. No test-based selection. All six methods run on the eight test hosts; no duplicate default/matched baseline runs. Ablation and payload sensitivity use the same eight test hosts and proposal only. Security, codec, streaming, video frame attacks, payload sensitivity and ablation explicitly run FC-AOIP only. All image attack cases retain 60 attacks, including unqualified/not-embedded rows.

Main also runs mathematics, security, real video codec/stream and video frame 60-attack experiments, and generates summary CSV/TeX and figures. Compute stress is optional via `--stage compute`. Default video protocol uses the original four real test clips (vidyo1, vidyo3, vidyo4, FourPeople); video downloads only. No video development/validation or synthetic fallback. Defaults: paper codec set, 100 frames/clip (rather than 1000), existing proposal-only resolution scaling through 4K, original streaming FPS, 10 sampled frames/clip for all 60 attacks and FC-AOIP only. Use `--video-profile lite` for a smaller codec/resolution/FPS grid, `--video-frames 1000` to restore original paper count, or `--video-input /path/real.mp4` for one local video. `--skip-download` uses a preverified video manifest/cache. Video failures are recorded, not hidden.

Stages: `calibration`, `hyperparameters`, `test`, `ablation`, `payload_robustness`, `security`, `video`, `video_frames60`, `mathematics`, `compute`, `summary`, `statistics`. Example: `bash run_12_images.sh --stage calibration --resume`, followed by `--stage test --resume`. Calibration must be complete before comparative test only; proposal-only security, payload and video can be run separately without calibration. `--keys 1` reduces image test/ablation/payload repetitions (calibration already one key; security has its own wrong-key count). Keep the same stage parameters when resuming. Each stage has SQLite case checkpoints; resume requires same code, config and environment and actual restored files. No automatic recovery from a different Kaggle worker. The output root is new and incompatible with prior compact runs.

The protected proposal, baseline and 60-attack source files are unchanged. Runtime benchmark comparisons still need dedicated measurement; video/large cases may take considerable time even with the compact image protocol.

Statistical exports: `bash run_12_images.sh --stage statistics --resume` analyzes the completed main robustness data (all expected attack rows required). Results are paired at host/key/watermark/condition and averaged at host level before an exact two-sided sign test, with Holm correction for five baselines. Report pair coverage and qualification separately; inference is conditional on jointly qualified returned cases, exploratory for eight previously used hosts. The script does not invent scores or p-values for missing comparisons. See `paired_sign_tests.csv`, `.tex`, `paired_host_differences.csv`, and `methodology.json` in the summary/statistics directory.

## Original watermark protocol

All media benchmarks use the bundled `data/watermark/wm.png` (C) and `data/watermark/Cc.logo.circle.png` (CC). Both are 64x64; alpha is composited on white before a grayscale threshold of 128 (white=1), then flattened in row-major order. No random media payload is generated. Every image host/key/configuration runs both logos with identical schedule and attack seeds across methods. The 4096-bit default is exactly the binarized logo. Other lengths use nearest-neighbor spatial resampling, not independently generated random bits. The image study therefore schedules 8 x 5 x 2 x 6 x 60 = 28,800 main attack rows. Calibration schedules 288 cases, hyperparameters 920, ablation 400, and payload 480. Security uses fixed target logos for wrong-key and unmarked trials; repeated trials vary the tested key. Video frames alternate C/CC by source frame index; per-frame extraction does not use temporal voting. Compute uses C for all methods and resizes it for capacity tests. Synthetic mathematical fixtures remain intentionally synthetic.

Each checkpoint manifest includes the original file hashes and canonical bit hashes. The new default output directory separates logo results from earlier random-payload results. Do not reuse old calibration or report previous random-payload scores as C/CC results. Pairing includes the watermark identifier. Summaries additionally export `watermark_summary.csv`. Because logo bit prevalence differs, compare BER as well as binary cosine NC; random-guess NC is not necessarily the same for both logos.
